# DeepTutor 原生按页、按需 OCR

已经部署到实际使用的 DeepTutor 桌面版，保留现有原生前端，不需要打开独立导入工具或切换 OCR 模式。

## 直接使用

1. 在 DeepTutor 的「沉浸式阅读」里，继续用原有「添加资料」入口选择 PDF。
2. 直接打开原文。此阶段不会识别整本书；扫描页没有文字也可以进入阅读。
3. 直接问「讲解当前页」或「讲解 PDF 第 30 页」。页码按 PDF 从第一页起数的物理页码解释，可能与书内印刷页码不同。
4. 正文足够时直接使用原文字；不足时自动在本机识别这一页。原界面活动区会显示「正在本机识别 PDF 第 N 页…」和完成时间。再次询问会显示缓存复用。
5. 失败时会说明原因。再次发送同一页请求可重试；空白识别结果不会被当成成功读取。

默认只准备当前页或明确指定页的首轮上下文；新增 OCR 遵守本轮任务范围。跨页、整份作业、全文搜索或总结任务可按需读取其他页面，并显示进度；扫描材料的大范围首次读取会较慢。没有任何全书后台预识别任务。

2026-11-12 修正：页面范围限制只约束**新增 OCR**，不再禁止读取当前原件的其他原生文字页或已有缓存页。“生成这份作业的完整答案”“按 Part A 要求生成答案”等会识别为跨页任务；“继续按原要求”可继承前面的用户任务。无需重新上传 PDF，也无需为同一文件反复授权。

跨页任务直接准备原生文字和已有缓存。未缓存的扫描页标为尚未读取，只有 `read_material` 实际需要这些页时才在本机识别，并显示进度。长文件仍按上下文预算分批读取，不能把预览或截断文字宣称为已经完整看过。

## 页面与缓存

原始 PDF 不修写；页面、公式图像、笔记、目录、原有批注、书签和阅读进度保留。OCR 文字只存在辅助缓存中，原有提取单元文件也不覆盖；已有注释的原文字偏移前缀保留。

缓存按源文件完整 SHA-256、物理页码、OCR 引擎/模型及关键参数隔离，并校验缓存内容哈希。相同页的并发请求由线程锁和文件锁合并，已有页不重复识别。

天津大学《高等数学（上册）》之前的 349 页识别结果继续保留且可以按页直接复用。本次没有重跑这本书的全书 OCR；可搜索 PDF、旧工具和旧缓存均保留。

本次新增缓存：`DeepTutor-native-ocr\cache`；复用缓存：`DeepTutor-conversion-tools\pdf-textbook-tool\cache`。中文 OCR 引擎和模型仍使用之前已验证的本地 RapidOCR / PP-OCRv3。仅缓存未命中的单页会启动本地工作进程，完成即退出；不增加开机启动或常驻 OCR 服务。

## 实测

- 文字页讲解没有 OCR 调用。
- 原生添加三页混合 PDF 后，未发生 OCR，原文直接可读。
- 明确请求扫描第 2 页时，日志只出现第 2 页的一次识别；首次识别约 **7.3 秒**。
- 再次请求第 2 页、以及桌面重启后再次请求，均命中缓存，没有重新识别；隔离测试缓存准备约 **0.02 秒**。
- 后来明确请求第 3 页，才识别第 3 页，约 **8.1 秒**。第 1 页始终没有 OCR。
- 原界面已显示首次识别提示和缓存复用提示，实际 GPT-6.1-Sol/high 回复分别引用正确的 `[p.2]`、`[p.3]`。
- 混合页判断、新文件缓存隔离、同页三路并发只识别一次、工具不能扩大单页范围、无文字 PDF 导入、空白识别失败及重试均有测试。
- 原件哈希、原页面显示、目录、批注、书签及阅读位置已核对。验收导航临时改变的一处位置已恢复为验收前第 110 页。

以上 OCR 时间不含模型生成讲解时间。实际桌面短回答约需二十至三十多秒，取决于模型、推理强度和工具调用。

## 限制

公式、上下标、希腊字母和手写批注仍可能识别错误，缓存不是逐式校对版；计算、抄题和引用公式以原图为准。原扫描页面保持图片，因此原 PDF 画布上的文字选择能力不会凭空变成完整的可搜索 PDF 文字层。

文字质量判断使用正文量、位置、长行、重复文字和图像覆盖情况的启发式，极特殊版式可能判断不准。纯插图或空白页可能没有可识别正文，会报告失败而非编造已读取的内容。

补丁固定部署在当前桌面 1.7.1 运行时；今后若更新/更换桌面运行时，需要核对并重新适配，不能默认更新后仍然加载本补丁。

教材不上传外部 OCR 服务。本地识别后的文字用于正常的阅读讲解，讲解仍由你当前选定的模型提供。
