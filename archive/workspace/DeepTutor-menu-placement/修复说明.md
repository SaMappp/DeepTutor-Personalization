# 沉浸式阅读伴读菜单向上展开

伴读输入框固定在阅读面板底部。此前空白对话误用普通聊天首页的向下展开规则，模型列表和推理强度菜单可能超出窗口。

修复仅在 `ReadingComposer.tsx` 的 `StandaloneComposer` 上启用已有的 `docked` 配置：菜单从首条消息之前就向上展开。输入区也使用已有的底部停靠间距和紧凑高度，普通聊天首页的布局不改。

已用现有依赖构建同版本前端，通过编译和 TypeScript 检查，部署到实际桌面运行时及加载缓存。旧前端目录保留为备份，路径与新旧构建 ID 见 `deployment.json`。

实际桌面验证包括空白伴读和已有对话中的模型、推理强度菜单；菜单均在触发按钮上方且完全位于窗口内。19 个模型选项可滚动查看，末项完整可见且点击命中区域没有遮挡。验证未发送模型请求或触发 OCR。

证据：

- `model-menu-up.png`、`last-model-visible.png`：模型菜单及末项。
- `effort-menu-up.png`、`existing-effort-menu-up.png`：强度菜单。
- `final-audit.json`：真实菜单坐标、数据和设置保留、OCR 补丁保留、调试端口关闭。

今后如替换整个桌面运行时，需要检查新版本是否已修复，或重新部署本次源代码改动。
