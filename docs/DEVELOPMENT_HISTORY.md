# 开发时间线

这份时间线从当前学习目录内最早的 DeepTutor 安装记录开始，依据现存说明、源文件、备份、部署清单和验证记录整理。没有找到更早版本的个人开发提交，因此不把文件修改时间伪装成 Git 历史，也不声称这些是最初每一次对话的逐字记录。

原始安装说明明确使用北京时间；其他记录使用本地时间、文件名时间戳或 UTC。下表沿用原说明中的日期／阶段，不把跨时区文件修改时间当成精确开发时刻。2026-11-10 为本仓库整理发布日期。

## 1. 2026-11-05：首次安装、登录与基本使用

从官方 PyPI 安装 `deeptutor[full]==1.7.1`，使用独立虚拟环境。通过 DeepTutor 自身的 Codex OAuth 登录；当时选定 GPT-6.1-Sol、推理强度 high，界面及回复使用中文。配置和模型版本属于当时状态，其他用户应使用自己的授权与可用模型。

原启动器的前后端监听改为 `127.0.0.1`。增加 Windows 启动、停止和登录入口；启动脚本检查端口归属、复用已有进程，并等待前后端就绪再打开页面。

安装早期第一次完整 CLI 测试曾等待较久而被中断，原因没有确定。随后 CLI、网页回复、健康接口及依赖检查通过；没有据此声称首次失败已定位。

证据：`archive/workspace/DeepTutor/安装验证记录.md`、`使用说明.md`；实现：同目录启动脚本及 `overrides/cli/deeptutor/runtime/launcher.py`。

## 2. 安装后：目录迁移与真实对话修复

迁移至统一的学习目录后，重建虚拟环境入口并保留原有数据。健康接口正常时，真实学习请求仍因工作区注册数据库保留旧绝对路径而失败。备份后只更新相关工作区路径；停止入口也补充了本实例残留服务的归属检查。

后续验证覆盖真实中文回复、历史重开、连续追问、停止／启动、重复启动和重启后会话保留。数据库原文件及备份属于私人数据，不在本仓库。该次数据库操作没有留下独立可复用迁移程序，因此本仓库只记录方法，不补造迁移源码。

证据：`archive/workspace/DeepTutor/整体检查记录.md`。

## 3. 2026-11-05—06：独立桌面版与 Codex 使用入口

下载官方 Windows v1.7.1 便携包，原记录核对了 Release SHA-256。桌面版使用自己的运行目录、登录和学习数据，与 CLI/PyPI 的同一运行目录分开。验证过桌面中文问答、关闭与图标重开。

在 Codex 的 DeepTutor CLI skill 中追加本机路径、默认模型和并发规则：同一运行目录的网页与 CLI 不同时拥有学习请求；确认无活动任务后才停止服务，任务完成后按原状态恢复。一次新的非交互 Codex 会话因沙箱限制未取得回答；后来单条获准 CLI 调用完成。该限制保留在历史说明中。

证据：`archive/workspace/DeepTutor/Codex与桌面版使用说明.md`；公开的通用工作流见 `docs/REPRODUCING.md`。本机 Codex 配置和授权未公开。

## 4. 2026-11-05—06：多来源模型与聊天推理强度

历史上接入 DeepWorks 企业积分通道，并随后接入 DeepSeek Harness 账号余额通道。模型列表标记来源，避免同名模型混淆计费。按后续要求恢复并固定原有默认 GPT-6.1-Sol/high；同步和临时测试其他模型不改变默认选择。

新增聊天输入区的推理强度按钮：只显示模型支持的等级，保存中锁定发送和模型切换；保存失败保留旧值。后端同步保存的等级到实际请求参数。普通聊天与停靠输入区采用相应菜单方向。

历史验证包括部分替代模型的真实中文响应、CLI 沿用会话模型选择，以及控件测试、TypeScript 检查和构建；没有逐一测试所有目录模型，也没有把钱包整体变化当成逐笔账单。

公开时保留接入设计及验证边界；DeepWorks 自动读取客户端专用凭据的原实现留在本机。`tools/provider_config.py` 是整理发布时新增的显式授权配置替代版，不冒充当年的原始实现。

证据：原模型说明的脱敏副本、`overrides/frontend/`、两套后端 `services/model_selection/llm.py`。接入授权区别见 `docs/PROVIDER_INTEGRATIONS.md`。

## 5. 2026-11-07：本地学习辅助与课程组织

新增独立本机认证服务，提供 Jina 中英 embedding、Whisper small 转写和 Edge 朗读转接。前两者本地计算；Edge 朗读需要网络。服务按需启动、仅监听环回地址，最后一个 DeepTutor 退出且没有请求后空闲退出。

启动入口先准备辅助服务。通过增量设置 API 配置两套 DeepTutor，保留默认模型。课程资料按科目建立工作区、知识库及阅读合集；两个实例分别导入并保存自己的索引与状态。

课程源清单、工作区 ID、实际材料、演示聊天和语音均不公开；保留组织与导入脚本。学习操作手册的公共工作流另行重写，个人学习计划未公开。

实现：`archive/workspace/DeepTutor-learning-support/`；说明：`docs/LEARNING_WORKFLOW.md`。

## 6. 2026-11-07—08：PPT 阅读、PDF 转换与批处理

为保留课件外观，增加 LibreOffice PPT→PDF 和 PDF→图片PPT 工具、去重导入脚本及输出核对工具。原件不覆盖，重复转换按源哈希跳过，同名不同内容另存。隐藏幻灯片纳入静态 PDF，保持页码对应。

一次课件页面中原本位于画布外的内容通过单页阅读修正版处理，其余页面及原件保留。修复代码公开，课件文件和生成结果未公开。静态 PDF 不保留动画、音视频或交互；没有承诺与 PowerPoint 逐像素一致。

实现及历史验收说明：`archive/workspace/DeepTutor-conversion-tools/`。

## 7. 2026-11-08 前后：全文 OCR 到可续作教材工具

先探索本地 OCR／可搜索 PDF 生成，再发展为中文 GUI 和通用流水线：检测已有正文，仅识别需要的扫描页；支持物理页码范围、部分输出标记、缓存校验、模型参数隔离、暂停续作、失败重试及内容去重导入。

历史记录有一本教材 349 页处理与逐页验证结果。教材、OCR 结果、缓存和所用页面图片均未公开。数学公式和手写内容仍有误识别，识别文字不能替代原图校核。独立 GUI 的完整点击验收曾被用户中止；接口核心流程通过，二者不混淆。

实现：`archive/workspace/DeepTutor-conversion-tools/ocr/` 和 `pdf-textbook-tool/`。

## 8. 2026-11-08—09：接入原生沉浸式阅读的按需 OCR

将“先处理整本书”改成桌面版原生阅读流程中的按页准备：导入扫描 PDF 不立即识别；讲解当前页或明确页码时，正文不足才启动单页本机 OCR。缓存按文件完整哈希、页码及引擎参数隔离；线程锁和文件锁合并同页并发请求。

工具不能把单页问题扩大为全书 OCR；只有明确跨页／全书意图才扩展范围。空白结果报告失败并允许重试。原始 PDF、已有批注、书签、进度与提取内容保留。该改动只部署到桌面后端，没有部署到 CLI 阅读流程。

收尾时还修复 Windows 从最小化恢复后内嵌前端尺寸未刷新的问题，为桌面壳增加 `restore/show` 布局事件。

实现：`overrides/desktop/`、`overrides/desktop-shell/`；历史说明：`archive/workspace/DeepTutor-native-ocr/使用说明与验证记录.md`。

## 9. 2026-11-09 前后：知识中心与阅读合集同步

两套后端分别增加知识库本地原文到阅读资料的桥接。上传和追加资料进入所属工作区阅读合集；哈希去重，优先复用匹配合集，同名新内容另加副本，删除知识库原文不级联删除阅读历史。

同步失败不撤销成功上传，进入阅读时可重试；支持本地且阅读器支持的文件，并遵守其大小限制。远程知识服务不被擅自下载，不重建索引、不触发模型请求或全文 OCR。

历史验证覆盖两环境各七项隔离测试、真实上传和工作区归属，另核对原资料与设置保留。

实现：两套后端的 `reading/knowledge_sync.py`、知识库路由与初始化／追加入口；历史测试：`archive/workspace/DeepTutor-knowledge-reading-sync/test_sync.py`。

## 10. 2026-11-09：伴读菜单向上展开

阅读输入区位于底部，空白伴读却误用普通首页的向下规则。`ReadingComposer.tsx` 启用已有 `docked` 配置，使模型和推理菜单从首条消息前就向上展开。没有改动普通聊天首页的方向规则。

历史记录包括构建、类型检查及实际桌面菜单位置／末项可见性核对，期间没有发送模型请求或触发 OCR。

实现：`overrides/frontend/web/components/reading/workspace/ReadingComposer.tsx`；历史说明：`archive/workspace/DeepTutor-menu-placement/修复说明.md`。
